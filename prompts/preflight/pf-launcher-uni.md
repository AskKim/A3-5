# Reusable Modular Release And Setup Launcher
> **Reusable Modular Rule:** Keep this top static header, master/guardrail handshake, and `=== CONSTRAINTS ===` block byte-identical to preserve prompt-cache prefix hits.
> - **Two File-Edit Setups:** (1) Retire completed `[FIRST-TIME-SINGLE-USE]` lines in place via `AGENT_SKIP_LINE` (never applied to `[REUSABLE]` lines); (2) log every completed step immediately to `docs/handoff-state.json` (Schema v2) using UTC ISO-8601 (`YYYY-MM-DDTHH:MM:SSZ`) and clear `last_error: null` upon any resumed step's clean completion.
> - **Branch, Version, Stale & Duplicate Guards:**
>   1. **Branch / Version Reset:** If `active_branch` or `target_version` differs from `<branch-name>` or `<version-tag>` (or user requests a branch-local reset), reset `active_branch`, `target_version`, `resume_cursor: null`, `phase_a_scope_hash: null`, `ai_studio_status: "pending"`, `ai_studio_completed_at: null`, `ai_studio_commit_sha: null`, `improvement_log_anchor: null`, `antigravity_status: "pending"`, `antigravity_completed_at: null`, and `last_error: null` (preserving `history[]` and all `AGENT_SKIP_LINE` markers).
>   2. **Stale Checkpoint (> `stale_hours`, default 24h) Or Phase A-Scope Delta = Hard Stop (Block Phase B):** If `ai_studio_completed_at` exceeds `stale_hours`, or if commits touched Phase A-scope paths (`src/`, `public/`, `index.html`, `package.json`, `manifest*`) after Phase A, or `improvement_log_anchor` / branch / version changed, print `STALE_BLOCKED`, log `last_error`, and halt until Phase A is rerun in AI Studio. Phase B-scope edits (`THIRD_PARTY_NOTICES.md`, `.github/workflows/*`, `CHANGELOG.md`) must NOT falsely invalidate Phase A during a Phase B resume.
>   3. **Duplicate Guard (this is what makes a step once-per-release):** Before executing any `[REUSABLE]` step, check `history[]` in `docs/handoff-state.json`. If already `completed` for `<branch-name>` + `<version-tag>` + current `HEAD` (unless `--force-rerun <step_id>` is passed), notify the user with `completed_at` and ask whether to continue or abort.
Read `prompts/master_system_prompt.md` completely, enforce all architectural, scope, type-safety, and output rules, and confirm it outputs `ALIGNED` (or `aligned`) before running steps below.
Read `prompts/preflight/run-uni/guardrails.md` completely, enforce every Hard Stop, Architecture, Data-Safety, Scope, Git, and Token-Efficiency guardrail, and confirm it outputs `GUARDED` (or `guarded`) before executing any step. If either check fails or any step conflicts with a guardrail, record `last_error` in `docs/handoff-state.json`, execute step-scoped rollback ONLY on files touched by the failed step, print `STEP_BLOCKED [<step_id>]: <1-2 line reason> | Reverted: <files> | Resume: fix issue and re-run launcher.`, and stop.
=== CONSTRAINTS ===
1. Read `prompts/preflight/preflight.config.json` first if present to auto-load static repo parameters (`repo_url`, `live_url`, `subpath`, `dev_branch`, `release_branch`, `phase_a_scope_paths`, `stale_hours`). Stop and ask the user only for missing parameters, dynamic run values (`<branch-name>`, `<version-tag>`), optional flags (`--dry-run`, `--force-rerun <step_id>`), and upfront confirmation of which runner you are (`ai-studio`, `antigravity`, or `freebuff`); never re-prompt mid-run.
2. **Self-Identify First, Probe Second:** You know which runner you are; state it once. Then confirm the one capability that matters: does a local Git CLI / shell / wrapper tool exist? If it does not, you may only take Phase A steps; if it does, you may take Phase B steps too. If your self-identification and the capability probe disagree, stop and ask once upfront.
3. **Follow The Runner Bracket:** Each step line carries an ordered bracket, e.g. `[ai-studio | freebuff]` or `[antigravity | freebuff]`. You may run a step only if you are named in its bracket, and the first named runner is the preferred one. Phase A is the cheap tier; Phase B is the local tier. Never take a step you are not named in, and never claim a step you cannot finish end to end.
   **Never stop a runner that can continue:** if you are named in the *next* block's bracket, finish this block and run straight on into the next one in the same run - no hand-off line, no "go to Anti-Gravity" reminder, no waiting for the human. A stop at a block boundary is correct **only** when the next block does not name you.
4. **Front-Load Cost, Not Just Capability:** Phase A exists because those steps need no environment access **and** because the sandbox tier is the cheapest place to run them. Never move a Phase A step to a higher-cost runner merely because that runner could do it. If you are a higher-tier runner holding unclaimed Phase A steps, say so in one line, name the steps, and let the human decide before spending.
5. Preserve boot/entry stability, existing runtime/CI behavior, pure TypeScript `src/engine/` & `src/domain/` with zero browser DOM coupling, and unencrypted local database invariants.
6. Enforce `ROADMAP.md` boundaries (`For This Version` vs. deferred/out-of-scope); never silence TypeScript errors with `as any`, `@ts-ignore`, or `@ts-expect-error`; never write personal legal names into repo artifacts.
7. **Step-Scoped Atomic Rollback (Never Blanket `git checkout -- .`):** Inspect `git status -s` before each step (in `antigravity`, optionally capture a non-destructive `git stash create` pre-step reference or use `node prompts/preflight/scripts/preflight-rollback.mjs`) and record `touched_files[]`. If `git status -s` shows unrelated uncommitted changes at start, halt with `STEP_BLOCKED` and ask before continuing. On failure, revert ONLY the failed step's files (`git checkout -- <failed-step-files>` and remove only untracked files created by that step), preserving `docs/handoff-state.json`, prior completed steps, and `AGENT_SKIP_LINE` edits.
8. **Token Discipline & Modes:** Scope reads to required files and diff stats; never dump full trees or passing CI logs. In `--dry-run` mode, validate config/platform/freshness and print the planned `SKIP`/`RUN` table without editing any files.
