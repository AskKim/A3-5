## Quick Non-Negotiables (For Inline / Read-Only / Fast Context)
- **Startup Check:** On active coding tasks, emit `ALIGNED` followed by `PENDING HANDOFF: <path> — <goal>` / `PENDING PLAN: <path> — <goal>` or `NO PENDING WORK` (`docs/plans/`, excluding `suggestions-backlog.md`).
- **React PWA Only:** Core app (`src/`, `index.html`, `vite.config.ts`, `package.json`) MUST stay React + Vite + TypeScript (ES2018 target). `android-wrapper/` is strictly a thin Kotlin WebView shell—never rewrite the PWA in Kotlin.
- **Three-Layer Boundaries:** `@engine/*` (`src/engine/` — zero livestock/pedigree terms, zero DOM outside `bridge/` & `storage/`), `@features/*` (`src/features/` — zero cross-feature sibling imports), `@domain/*` (`src/domain/` — pure TS, zero DOM), `@app/*` (`src/app/` — composition root). Never import from `/import/` or `/old/`.
- **Strict Safety & Dates:** Never use `as any`, `@ts-ignore`, or `@ts-expect-error`. Store pure calendar dates as `"YYYY-MM-DD"` strings and compute offsets via `Date.UTC(y, m, d + offset)`. Protect `src/main.tsx`, `src/App.tsx`, `index.html` (`BOOT_ENTRY_LOCK_CHECKSUMS`) and `/prompts/` files.
- **Token-Saving Edits (Required):** Change existing files with targeted diffs (`str_replace` / patch), never whole-file rewrites; report `git diff`, not full files; read only the needed line window; batch independent tool calls; keep scratch files in `/tmp`; never re-save account skills just to check read-back. Full rules: `AGENTS.md` §6.
- **Verify:** Run `npm run verify` (typecheck, tests, coverage floor, and the registry / prompt / module / layer / engine / extraction / Android / store-contract invariants) plus `npm run build` before finishing code changes; run `npm run verify:chunks` on the built output when imports changed. Log significant changes as a registry entry in `src/domain/improvements/registry-part-*.ts` with `decidedOn`/`status`/`rejected` and regenerate the ledger with `npm run regen:ledgers` — never hand-edit the generated region, which `npm run verify` re-renders from the registry. Prompt revisions go in `src/domain/promptRegistry.ts` with `decidedOn` + `version` + `commitShaOrTag` (optional `supersedes`; `supersededBy` whenever `status: superseded`) and are gated by `npm run verify:prompts` (both ledger gates run in CI), which rejects a half-opted-in entry, a `superseded` with no `supersededBy`, and any new entry outside the pinned `LEGACY_*_ENTRY_IDS` lists that omits the ledger fields; they also reject a `decidedOn` that is not a real calendar date and a `supersededBy` that names no registry entry.
